01 · 표시 방식

세로 사진을 넓게 자릅니다

02 · 원본과 초점

같은 인물도 소스 규칙이 다릅니다

프로필·배너·캘린더가 별도 원본을 선택합니다. 일부 데이터 경로는 이미지 위치를 전달하지 않아 CMS에서 조절해도 전체에 적용되지 않습니다.

03 · 전달 해상도

표시 폭만으로는 해상도가 부족합니다

모바일 홈의 가로 포스터가 세로 영역을 채우면서 약2.5배 확대됩니다. sizes에도 cover 확대량 또는 적합한 파생본을 반영해야 합니다.

같은 사진이 다르게 보이는 이유

직접 캡처한 로컬 화면입니다. cover는 사진을 찌그러뜨리지 않고 잘라 채웁니다. 원본 전체를 보존해야 하는 포스터에는 다른 규칙이 필요합니다.

잔존 면적은 기하학적 계산이며 얼굴 품질 점수가 아닙니다. 오버레이·CSS 추가 zoom은 별도 검토해야 합니다. 이미지를 누르면 캡처 원본을 볼 수 있습니다.

코드로 강제할 수 있습니다

현재의 CreatorImage를 확장하고 CMS 입력·게시까지 같은 계약을 적용합니다. 컴포넌트 이름만 공통화하면 원본 비율과 임의 CSS를 막을 수 없습니다.

1. 원본 정보서버에서 치수·형식·revision 검사. URL만 저장하는 경로를 보완합니다.
2. 용도별 binding프로필·세로·가로별 원본과 slot을 연결하고 crop·safe area·파생본을 승인합니다.
3. 공통 renderer화면은 slot만 선택합니다. src·fit·position·scale은 호출자가 바꾸지 못하게 합니다.
4. 게시·CI 검사미충족 자산 게시와 직접 Image 우회를 막고 로컬 렌더로 얼굴·글자를 확인합니다.
  1. 현행 화면 규격부터 코드에 명시원본 교체 영향 범위와 초점 DTO 누락을 정리합니다. 기존 승인 구도는 보존합니다.
  2. CMS metadata와 게시 검증 추가신규·수정 자산부터 적용하고 기존 공개 데이터는 호환 경로로 유지합니다.
  3. 실제 crop 개선을 단계적으로 적용모바일 홈 포스터와 PC 인물 배너부터 수정한 뒤 Passport·캘린더·경품으로 넓힙니다.

이번 산출물은 조사 문서와 적용안입니다. 제품 코드·운영 데이터를 변경하지 않았습니다. 비공개 사용자 사진·인증 화면·관리자·실제 SNS 콘텐츠는 직접 렌더하지 않았으며, 상세 근거와 미확정 선택은 전체 문서에 기록했습니다.
