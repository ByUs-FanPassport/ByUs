# Admin 목록 기본 동작 수정 — 2026-09-12

## 검토 결과와 수정

| 대상 | 확인한 문제 | 수정 |
|---|---|---|
| 크리에이터, LIVE, 혜택·응모, 인증 미션·심사, 공지, 관리자 | 전체 목록을 그대로 표시, 페이지 이동 없음 | 공통 20건 페이지 이동, 범위·현재 페이지 표시, 검색 변경 시 첫 페이지, 결과 감소 시 페이지 보정 |
| LIVE, 혜택·응모, 인증 미션, 공지 | 목록 검색 부재 | 전체 응답 목록을 대상으로 검색 후 페이지 구분 |
| 디지털 발급 내역, 알림 전송 | 첫 50건 이후 이동 없음 | 서버 tuple cursor, 1건 lookahead, 이전 내역 더 보기 |
| 공지 댓글 | timestamp 단독 커서로 동일 시각 데이터 누락 가능 | `(createdAt,id)` 커서, lookahead, 이전/다음 이동, 실패 후 이전 페이지 복귀 |
| 팬 라운지 | 이전 페이지 복귀가 최신 페이지로만 가능 | 커서 이력에 따른 이전/다음 이동, 오류 시 이전 이동, 숨김 처리 중 이동 차단 |
| 회원 | 정확히 50건일 때 불필요한 다음 페이지 표시 | 한 행 추가 조회로 다음 페이지 존재 확인 |
| 감사 로그 | 이전 내역 실패 표시 없음, 필터 변경과 요청 경합 | 오류·재시도, 요청 취소·오래된 응답 무시, 중복 행 제거 |
| 크리에이터·혜택·공지 | 일부 읽기 실패 시 재시도 불가/로딩으로 남음 | 실패 상태와 재시도 경로 |
| CS 문의 | 기존 tuple cursor, lookahead, 이전/다음 정상 | 유지 |

번호 페이지는 전체 데이터를 받는 기존 CMS API 위에서 동작한다. 이 변경은 전체 CMS 응답의 서버 쿼리 비용까지 줄이는 변경은 아니다. 대규모 혜택 응모·수령 내역의 서버 페이지 분리와 상세 지연 조회는 별도 설계 범위다. 편집 중인 항목은 ID로 유지한다.

## 검증

- Admin UI/analytics/auth 관련 기존 CI 명령: 48개 파일, 264개 테스트 통과.
- 추가 API/커서 집중 검사: monitor 7개 파일 29개, comment/fan 3개 파일 27개 테스트 통과.
- 웹 lint, TypeScript, Next production build 통과.
- 깨끗한 PostgreSQL에서 전체 150개 마이그레이션 적용. `supabase/tests/admin_monitor_pagination.sql`, `supabase/tests/admin_comment_fan_pagination.sql` 통과: 동일 timestamp 경계, 범위, actor 및 execute 권한, 알림 함수 VOLATILE 확인. 합성 fixture는 rollback.
- 실제 컴포넌트·CSS를 로컬 Vite harness에서 렌더링. auth와 API는 합성 fixture. 1440px/390px에서 크리에이터, LIVE, 혜택, 인증 심사, 인증 미션, 공지, 관리자, 발급 내역, 알림, 감사 로그, 댓글, 라운지의 페이지 전환 24개 조합 확인. 운영 계정/데이터 변경이나 운영 화면 검증으로 간주하지 않는다.
- 인증 심사 선택 항목 전환, 마지막 페이지 보정, 검색 후 첫 페이지, 페이지 로딩 실패·중복 데이터·진행 중 변경 차단 회귀 검증 포함.
