# 유료 멤버십 인증 파일럿 구현·배포

## 승인 범위와 제품 동작

- 사용자가 2026-09-11 승인한 범위: 플랫폼 예시 화면 제작을 기다리지 않고 필수 정보를 안내해 인증 자료를 수집한다. 팬이 제출하고 관리자가 승인하거나 사유를 적어 보완을 요청한다. 승인하면 스탬프와 팬 점수를 한 번 지급한다. 구현과 배포 완료까지 진행한다.
- Instagram, TikTok, YouTube별 인증 미션을 기존 수동 인증에 추가한다. 크리에이터 계정, 제출자의 플랫폼 계정, 현재 유료 멤버십 상태와 다음 결제일 또는 유효기간이 보여야 한다. 시작일·가입 기간은 선택 사항이다. 여러 화면으로 나뉘면 최대 3장까지 받는다. 결제수단·다른 개인정보는 가릴 수 있다.
- 무료 팔로우·무료 채널 구독은 대상이 아니다. 체험/선물 여부 자체로 자동 승인하지 않으며, 관리자가 현재 유효한 유료 멤버십을 확인한다. 확인에 필요한 정보가 부족하면 보완을 요청한다.
- 작업 가정: 크리에이터별·플랫폼별 최초 1회, 스탬프 1개와 점수 1점, 응모권 0장. 점수는 기존 미션의 불변 보상 스냅샷으로 관리한다. 사용자에게 비동기 질문을 제시했으며 별도 답이 오면 반영한다. 정기 재인증·기간 비례 점수·구독 결제는 범위 밖이다.

## 구현 계획

1. 기존 `certification_missions`에 nullable `membership_platform`을 추가하고 크리에이터+플랫폼 조합을 유일하게 한다. 일반 수동 미션은 null을 유지한다. 생성 시 지정하며 변경하지 않는다. 기존 관리자 save RPC는 기존 호출 호환성을 유지하는 확장 RPC를 통해 플랫폼을 지정한다. 회원 인증 보상은 점수 양수, 응모권 0을 강제한다.
2. 제출 시 플랫폼을 서버에서 스냅샷으로 저장한다. 팬이 플랫폼/보상/심사 상태를 보내서 변경할 수 없다. 기존 업로드 소유권, Passport 보유, 비공개 Storage, 만료, 최대 3장, 재제출·중복 방지 규칙을 보존한다.
3. `fan_activity_type`에 `membership`, 활동 출처에 `certification_submission`을 추가한다. 출처 검증은 같은 사용자·크리에이터의 승인된 회원 인증 제출만 허용한다. 기존 점수는 `manual_submission_id` 원장을 그대로 사용해 이중 점수를 피한다. 조회 시 회원 활동과 이 점수 원장을 연결한다.
4. 기존 심사 RPC 승인 트랜잭션에서 활동 → 기존 점수 → Stamp 및 블록체인 작업을 원자적으로 생성한다. 동일 Passport와 Privy 내장 지갑을 확인하고 없으면 승인 전체를 롤백한다. 기존 심사 멱등키·행 잠금·수정 버전 검사와 Stamp별 canonical operation key를 유지한다. 반려·보완 상태에는 보상이 없다.
5. Passport/스탬프/관리자 조회의 유형·합계·활동 출처와 UI 메타데이터를 확장한다. 체인 발급 대기와 업무상 발급을 기존 방식대로 구분한다. 회원 활동을 가짜 LIVE에 연결하지 않는다. 기존 티어·혜택 투영과 First Reaction을 보존한다.
6. 팬 제출 화면에 필수 정보 목록, 선택 정보, 개인정보 가림 안내, 플랫폼·보상·1회 안내를 표시한다. 회원 인증의 반려 표시는 `보완 필요`, 재제출 버튼은 `보완 자료 제출하기`로 한다. 관리자에는 플랫폼·검토 목록·보완 사유·승인 시 보상 정보를 보여준다. 일반 수동 미션 의미는 유지한다.
7. 블록체인 worker의 닫힌 타입 enum에 `Membership`을 추가하고 신규 스탬프의 공용 이미지를 공개 불변 IPFS URI로 고정한다. 기존 자산 base CID와 발급된 메타데이터는 유지한다. Solidity mint에는 타입 enum이 없어 컨트랙트 재배포는 하지 않는다.
8. 게시된 크리에이터의 등록된 플랫폼 계정을 읽어 해당 플랫폼용 파일럿 미션을 준비한다. 공개 소셜 계정 존재를 실제 유료 멤버십 제공의 확인 사실로 혼동하지 않는다. 활성화 범위와 실제 미션 ID, 데이터 변경 전후를 배포 기록에 남긴다. 인증 유무는 심사에서 판단한다.
