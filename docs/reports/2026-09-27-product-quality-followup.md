## 콘텐츠와 실제 원인

변경 전 엘리나 공개 API는 팬 글 0개, 공지 1개, 공지 미디어 0개, Instagram 0개였다. 팬 글은 사용자 작성 콘텐츠이므로 임의 생성하지 않았다. 기존 공식 소식을 같은 화면에서 찾기 쉽게 배치했다.

운영 YouTube 환경변수가 유효하지 않아 Google API가 400/API_KEY_INVALID를 반환했다. 기존 ByUs 프로젝트의 YouTube 전용 제한 키로 복구했다. 공식 published social link → channels API의 채널 ID·uploads playlist → 최근 6개 → videos API의 공개·채널 일치·비방송 검증 순서로 읽는다. 검색어로 동명이인을 매칭하지 않으며, 비공개·미등록·진행/예정/종료 방송은 일반 영상 피드에 섞지 않는다. 게시 여부는 요청마다 재확인하고 외부 API만 15분 캐시한다.

Instagram 데이터가 없는 계정의 사진이 자동으로 생기는 것은 아니다. 기존 연결 권한과 수집 계약을 유지하며 공식 채널로 이동할 수 있다.

LIVE 활성 당시 playback API 200, CDN 데이터 전송, CORS, H.264/HE-AAC를 확인했다. 이후 방송이 종료되어 수정 후 실제 영상의 재생 시간 증가까지는 재확인하지 못했다. 실패·종료·미지원 복구와 정상 응답 시각 오차는 회귀 테스트로 검증했다.

## 벤치마크 및 독립 검토

PM·알림/언어 UI·LIVE 안정성을 별도 스레드로 진행했다. PM이 계획과 데이터 경계를 검토하고 구현 후 API/권한/부분 실패를 다시 확인했다. UI 담당자가 게시판·미디어·신청 화면을 독립 검토하여 모바일 탭 정렬, 단색 게시 버튼, 빈 검색 결과의 신청 강조를 보완했다.

- YouTube 공식 채널의 [동영상](https://www.youtube.com/@YouTube/videos)·[게시물](https://www.youtube.com/@YouTube/posts) 실제 화면: 채널 정체성, 콘텐츠 탭, 썸네일과 메타, 게시물 출처의 분리를 참고했다.
- [YouTube uploads 조회 계약](https://developers.google.com/youtube/v3/docs/playlistItems/list), [공개 영상·방송 상태 계약](https://developers.google.com/youtube/v3/docs/videos)을 구현 근거로 사용했다.
- Weverse/Berriz 공식 App Store 이미지도 확인했으나 확보된 이미지는 마케팅 비주얼에 가까워 직접 UI 구현 근거에서는 제외했다.

## 검증 근거

- 알림·언어 및 영향받은 계약 108개 통과.
- 게시판·신청·미디어·YouTube 및 팬페이지 영향 검사 73개 통과. 이후 미디어/작성기 보완 15개, 방송 제외·publication 확인 4개 통과.
- LIVE 회귀 58개 통과. 기존 만료·restricted/unsafe URL 경계 유지.
- 로컬 1440px/390px에서 14개 화면·상태 확인: 접힌 작성기, 확장/공개범위/취소와 포커스, 미디어 실 이미지, 신청 진입·이름 전달, LIVE 복구, 가로 넘침 없음.
- 실제 공식 API에 최종 reader를 실행하여 공개·비방송 영상 6개 반환 확인.
- 별도 알림/언어 메뉴 PC·모바일 캡처와 Esc·query/hash 확인.

증거는 로컬 `work/product-quality-20260927/`에 보존한다. 로그·실제 화면·시험 데이터 화면을 구분하며, 개인정보가 포함될 수 있는 브라우저 원본 캡처와 환경변수는 저장소에 올리지 않는다. 배포 결과는 같은 디렉터리의 release 기록에 이어 기록한다.
